# Assay：别再让“当时为什么这么选”消失

每个用 AI 做项目的人，可能都经历过这条路径：看到一个不错的框架，大概看看，抄一点能用的代码，然后继续往前赶。三个月后再回头，已经说不清为什么选它、当时比较过什么、哪些部分刻意没采用，更不知道原来的判断现在是否还成立。

问题通常不是“没收藏”，而是研究、决策和落地之间断了线。链接躺在书签里，结论散在聊天记录中，复制进项目的做法失去了出处；AI 换了会话，人也换了上下文，许多判断只剩一句“之前好像是这么定的”。

## 从看过，到留下可追溯的判断

Assay 是一个开源的 CLI 工作台，名字来自 assay /əˈseɪ/：化验矿石，确定它由什么组成。它想做的事也很直接：**Study many. Build your own. 博采众长，自成一体。**

你可以把外部框架、库、模式或想法记为 Source，再通过 Analysis 留下你实际看了什么、怎么判断。一次评估不以“读完了”结束，而是明确写下“采纳 / 拒绝 / 继续实验”，并把证据一起保存。这样以后再问“为什么采用这部分、为什么放弃另一部分”，答案不必靠记忆或重新翻完整段对话。

真正验证有效的内容，可以通过 adoption 记录它如何进入你自己的 System 或 Knowledge。Assay 不是替你做决定，也不要求为了流程而走流程；它更像一套小而严格的工作台，让外部材料、判断依据和最终采用之间保持连接。

## 让长期项目跨过会话边界

研究之后还要继续建设。Assay 用带稳定身份的 Task、Roadmap 和 Spec 保存具体工作、方向与验收信息。即使 AI 会话结束、切换助手或上下文被压缩，下一次仍能找到同一个任务和它的来路，而不是重新猜“现在做到哪了”。

它适合经常评估开源项目、需要把外部方法引入自己系统的人；适合与 AI 助手共同推进数周或数月项目的人；也适合重视证据，希望把探索过程沉淀成长期知识的个人或小团队。
