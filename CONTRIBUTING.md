# Contributing

Assay should stay reusable and publishable. Keep changes focused on the CLI, core package, Skill, framework templates, architecture decisions, docs, and sanitized examples.

## Repository map

```text
packages/assay-core/          framework operations, schemas, templates, update, conversion
packages/assay-cli/           Commander CLI adapter over assay-core
skills/assay-builder/         agent-facing Skill that calls this repo's CLI
examples/framework-template/  sanitized generated workspace
docs/                         command docs, workspace docs, background, and decisions
scripts/                      validation, smoke, and install helpers
```

`assay-core` owns behavior. The CLI should parse options, call core APIs, format output, and map exit codes.

## Local development

Use Node.js >=22.13.0 and the repository-pinned pnpm 11.3.0. Older Node
versions are outside the supported install and CLI runtime contract.

```bash
pnpm install
pnpm build
pnpm typecheck
pnpm lint
pnpm test
pnpm smoke
```

Run the full repository check before committing:

```bash
./scripts/check.sh
```

On Windows PowerShell:

```powershell
.\scripts\check.ps1
```

The full check runs build, typecheck, lint, tests, the CLI smoke flow, and the committed public-example gate.

### Tests must not touch the user workspace index

Lifecycle and read commands do not track workspaces. Tests for explicit `workspace` commands must set `ASSAY_WORKSPACES_ROOT` to a disposable directory or pass `indexRoot` to core APIs. The Vitest global and worker setup enforce a disposable override and never inspect, read, or migrate the user's real index.

## Public example

`examples/framework-template/` is a sanitized workspace generated by the built TypeScript CLI. The release scripts validate it with:

```bash
node packages/assay-cli/dist/cli.js check --root examples/framework-template
node packages/assay-cli/dist/cli.js update --root examples/framework-template --dry-run
```

Regenerate the example from a temporary `study` workspace created by the built CLI, then remove runtime-only ledgers and local machine state before copying it into `examples/framework-template/`.

## Public boundary

Do not commit:

- real external-system snapshots, private references, customer or project data, generated releases, or runtime logs;
- `.env` files, API keys, tokens, credentials, or local absolute paths;
- one-off delivery reports, temporary validation output, caches, or compiled artifacts;
- runtime contents under `.assay/backups/`, `.assay/events/`, or `.assay/.runtime/`.

Use sanitized examples when a workflow needs demonstration data. Public docs should explain product behavior and reader actions, not private context, temporary acceptance criteria, or implementation diary notes.
